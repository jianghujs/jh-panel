## ADDED Requirements

### Requirement: 全部备份使用执行时服务器名单

本地目标的 MySQL 与 PostgreSQL 全部备份 SHALL 在每次运行时查询对应数据库服务器，以查询成功后的实时名单决定范围，不使用本地 SQLite 数据库清单作为备份范围来源。每个引擎 SHALL 在一次全部备份中获取并复用一次名单快照，且查询与导出 SHALL 指向同一实例。

#### Scenario: 自动纳入本地尚未登记的新库

- **WHEN** 服务器存在业务库 `new_app`，插件本地没有该库记录，运行对应引擎全部备份
- **THEN** 本次名单包含 `new_app` 并对其执行备份
- **AND** 不要求用户预先点击“从服务器获取”或重新创建计划任务

#### Scenario: 排除仅本地残留的旧库

- **WHEN** 本地清单包含 `old_app`，服务器已删除该库
- **THEN** 全部备份不尝试导出 `old_app`
- **AND** 不自动删除该库本地记录及历史备份

#### Scenario: 使用非默认实例配置

- **WHEN** 插件实例使用非默认端口或 socket
- **THEN** 名单查询和实际导出使用该实例配置，而非系统客户端默认实例

#### Scenario: 名单获取后数据库发生变化

- **WHEN** 全部备份已取得名单，随后服务器新建或删除数据库
- **THEN** 本次不重复查询名单，后建库留待下次任务纳入
- **AND** 名单内后删库的导出失败如实计入本次失败

### Requirement: 全部备份沿用系统库过滤规则

MySQL 全部备份 SHALL 排除 `information_schema`、`performance_schema`、`mysql`、`sys`；PostgreSQL 全部备份 SHALL 排除模板库和 `postgres`。系统 SHALL 去重名单并保留数据库名称原义。

#### Scenario: MySQL 系统库不进入全部备份

- **WHEN** 实时结果包含四个 MySQL 系统库和业务库 `app`
- **THEN** 仅 `app` 进入本次备份范围

#### Scenario: PostgreSQL 模板库不进入全部备份

- **WHEN** 实时结果包含 `datistemplate=true` 的库、`postgres` 和业务库 `app`
- **THEN** 仅 `app` 进入本次备份范围

### Requirement: 指定单库以服务器存在性为准

指定单库备份 SHALL 验证服务器上的指定目标，只处理该目标，不因本地清单缺失而误判不存在，不补登记或备份其他库。全部备份的系统库过滤规则 SHALL NOT 被用于额外禁止已有显式单库目标。

#### Scenario: 指定尚未登记的业务库

- **WHEN** 指定库在服务器存在而本地无记录
- **THEN** 系统只为该库补登记并备份，不处理其他实时发现的库

#### Scenario: 指定库已从服务器删除

- **WHEN** 指定库在本地有记录但服务器不存在
- **THEN** 系统明确报告目标不存在并以非零状态退出
- **AND** 不生成成功备份记录，不执行该库历史清理

### Requirement: 本地记录只增补不覆盖

系统 SHALL 为服务器确认存在且属于本次目标的未登记库补充现有插件兼容的本地记录，以关联有效 `pid`；已有记录的 ID、备注、账号、密码和访问字段 MUST 保持不变。补登记 SHALL NOT 创建服务器数据库、用户或授权。

#### Scenario: 保留已有管理信息

- **WHEN** 本次目标库已有本地记录和自定义备注
- **THEN** 备份复用原 ID，所有已有管理字段保持不变

#### Scenario: 并发任务已经补登记

- **WHEN** 目标库在本次检查后由另一任务补入有效本地记录
- **THEN** 本次可复用该记录，不盲目重复新增

#### Scenario: 本地补登记失败

- **WHEN** 写入失败或不能取得唯一有效本地 ID
- **THEN** 该库报告登记失败，不以空 ID 记录成功或执行历史清理
- **AND** 全部备份继续处理同引擎其他目标，最终返回失败

### Requirement: 查询失败与空名单明确区分

系统 SHALL 验证查询执行状态和结果格式，区分查询失败、未安装和合法空名单。查询失败、超时、配置损坏、异常对象或畸形结果 MUST 报错，MUST NOT 回退本地旧清单或误报无库。名单查询 SHALL 有有限等待，外部查询进程超时后 SHALL 被终止并回收。

#### Scenario: 服务器不可连接或无查询权限

- **WHEN** 已配置引擎的实时查询因连接或权限错误失败
- **THEN** 本次该引擎不执行导出、补登记或历史清理，命令非零退出
- **AND** 日志包含引擎、失败阶段及脱敏错误摘要

#### Scenario: 查询返回异常对象或畸形数据

- **WHEN** 查询工具返回异常对象、错误字符串或缺少预期字段的结果
- **THEN** 系统按查询失败处理，不按空名单成功处理

#### Scenario: 查询成功但没有业务库

- **WHEN** 查询成功且过滤后的名单为空
- **THEN** 日志明确显示无业务库，命令成功退出
- **AND** 不执行导出、补登记或历史清理

#### Scenario: 全部备份涉及未安装的引擎

- **WHEN** 全部备份对应插件的本地配置库不存在
- **THEN** 保留原有明确跳过行为，不尝试连接或创建配置
- **AND** 配置库存在但关键配置损坏或缺失时按失败处理，而非跳过

#### Scenario: 指定单库所需引擎未安装

- **WHEN** 指定单库的插件未安装或缺少所需配置
- **THEN** 命令报告该目标不能备份并非零退出，而非成功跳过

### Requirement: 已有任务和输出协议兼容

系统 SHALL 保留 `database`、`mysql_database`、`pg_database` 命令及原参数、旧裸库名、旧 `backupAll`、数据库类型筛选、文件格式和保留参数。不改任务页面与第三方备份目标链路，不要求重新创建已有本地备份任务。

#### Scenario: 类型范围保持不变

- **WHEN** 执行 MySQL-only、PostgreSQL-only 或两类全部备份任务
- **THEN** 仅执行其原有类型范围内的备份，各引擎使用实时名单

#### Scenario: 旧全部备份任务

- **WHEN** 旧任务调用 `database backupAll`
- **THEN** 保留 MySQL 后 PostgreSQL 的类型范围与顺序，并采用实时名单

#### Scenario: 数据库名称包含特殊字符

- **WHEN** 合法目标名包含空格、引号或 shell 元字符
- **THEN** 查询、备份参数和路径保持其字面含义，不执行名称中的 shell 内容
