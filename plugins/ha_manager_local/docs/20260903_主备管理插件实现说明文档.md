# 主备管理插件实现说明文档

## 插件功能介绍

主备管理插件用于在当前服务器上完成主备角色切换的本机侧操作。

插件的核心特点是：流程配置化、步骤可编辑、执行可重复、日志可追踪。操作员可以在切换弹框中查看每一步将要执行的脚本，也可以在执行前临时修改脚本；执行过程中前端持续读取日志文件，显示实际执行脚本、命令输出和退出码，便于判断当前步骤是否真正完成。

| 功能 | 说明 |
| --- | --- |
| 总览状态 | 展示当前主备角色、OpenResty 对外服务状态、自检状态和云监控配置 |
| 从切主 | 按配置步骤执行数据库升主、同步任务开启、备份策略调整、通知开启、OpenResty 启动、角色标记和自检 |
| 主切从 | 按配置步骤执行 OpenResty 关闭、数据库降从、主从检查、同步任务关闭、通知关闭、备份策略调整、角色标记和自检 |
| 步骤执行 | 支持“执行当前步骤”打开代码编辑框，也支持“继续执行”直接执行配置脚本 |
| 日志追踪 | 每次执行生成独立日志文件，前端定时读取并展示日志内容 |
| 异常提示 | 每个步骤可配置异常处理提示，配置后前端显示异常提醒入口 |
| 自检状态 | 按当前主备角色检查 OpenResty、文件同步、计划任务、监控提醒和角色标记，异常只提示不阻断切换 |
| 面板标识 | 安装主备管理插件后，面板 title 显示 `[主]` 或 `[备]` 标识 |

## 整体结构

| 模块 | 路径 | 说明 |
| --- | --- | --- |
| 插件目录 | `/www/server/jh-panel/plugins/ha_manager_local` | 主备管理插件代码目录 |
| 页面入口 | `/www/server/jh-panel/plugins/ha_manager_local/index.html` | 加载插件页面和前端脚本 |
| 前端逻辑 | `/www/server/jh-panel/plugins/ha_manager_local/js/ha_manager_local.js` | 总览、切换弹框、代码编辑、日志轮询 |
| 后端入口 | `/www/server/jh-panel/plugins/ha_manager_local/index.py` | 状态读写、步骤执行、日志读取、服务控制 |
| 流程配置 | `/www/server/jh-panel/plugins/ha_manager_local/flow_config.json` | 主备流程、步骤脚本、异常提示配置 |
| 运行目录 | `/www/server/ha_manager_local` | 插件运行数据和日志 |

## 数据结构

### 运行配置

存储位置：`/www/server/ha_manager_local/data/config.json`

用途（关键词）：本机身份、当前角色、期望角色、云监控配置、最近动作。

```jsonc
{
  "host_id": "H_LOCAL_xxx",        // 本机唯一 ID
  "host_name": "BK100-33",         // 面板标题
  "host_ip": "192.168.x.x",        // 本机 IP
  "pair_id": "",                   // 主备组 ID，占位配置
  "pair_name": "",                 // 主备组名称，占位配置
  "monitor_url": "",               // 云监控地址
  "report_interval": 30,            // 上报间隔
  "last_report_at": "",            // 最近上报时间
  "role": "standby",               // 当前角色：master / standby
  "desired_role": "standby",       // 期望角色
  "switch_status": "idle",         // idle / running / failed
  "last_action": "等待操作",        // 最近动作
  "options": {}
}
```

### 步骤状态

存储位置：`/www/server/ha_manager_local/data/step_state.json`

用途（关键词）：步骤状态、日志文件引用、异常信息、自检提示。

```jsonc
{
  "standby": {
    "close_external": {
      "state": "done",             // pending / running / done / failed
      "run_id": "FLOW_xxx_LOCAL_xxx",
      "log_path": "/www/server/ha_manager_local/logs/steps/FLOW_xxx_LOCAL_xxx.log",
      "msg": "",
      "warning_msg": "",
      "updated_at": "2026-09-03 11:37:12"
    }
  }
}
```

数据流：`run_step` 执行时写入 `state`、`run_id`、`log_path`、`msg`、`warning_msg`。

### 步骤日志

存储位置：`/www/server/ha_manager_local/logs/steps/<run_id>.log`

用途（关键词）：单次执行日志、脚本内容、命令输出、退出码。

日志内容包括：

- 当前步骤标题
- 预期脚本
- 执行来源：步骤配置脚本 / 前端代码编辑框
- 临时脚本文件路径
- 实际执行脚本内容
- 命令输出
- `exit_code`
- 成功或失败结果

数据流：每次打开切换弹框生成新的 `flow_run_id`；每次执行步骤生成新的 `run_id`；后端写日志文件，前端定时读取该日志文件。

### 自检状态

存储位置：不单独长期保存为独立文件；`get_state` 会实时计算自检结果并写入 `/www/server/ha_manager_local/data/state.json` 的 `checks`、`health_status`、`health_text`、`external_closed` 字段。切换流程里的自检步骤如果发现异常，会把异常摘要写入 `step_state.json` 对应步骤的 `warning_msg`。

用途（关键词）：角色一致性、OpenResty 状态、文件同步状态、计划任务状态、监控提醒状态、异常提示。

返回结构示例：

```jsonc
{
  "checks": [
    {
      "group": "Web 服务",
      "name": "OpenResty",
      "expected": "备机应停止",
      "actual": "已停止",
      "status": "pass"
    }
  ],
  "health_status": "normal",
  "health_text": "正常",
  "external_closed": true
}
```

检查项按当前 `role` 计算期望状态：

| 分组 | 检查项 | 主机期望 | 备机期望 |
| --- | --- | --- | --- |
| 计划任务 | 备份数据库、xtrabackup、xtrabackup-inc 全量/增量备份 | 关闭 | 开启 |
| 计划任务 | 备份网站配置、备份插件配置、证书续签任务 | 开启 | 关闭 |
| 计划任务 | 恢复网站配置、恢复插件配置 | 关闭 | 开启 |
| SSH 同步 | `authorized_keys` 同步公钥 | 未授权 | 已授权 |
| rsync | rsyncd 任务 | 开启 | 关闭 |
| rsync | lsyncd 服务 | 运行中 | 已停止 |
| Web 服务 | OpenResty | 运行中 | 已停止 |
| 监控提醒 | 主从同步异常提醒、Rsync 状态异常提醒、SSL 到期提醒 | 开启 | 关闭 |
| 角色状态 | 本机角色标记 | `master` | `standby` |

## 接口设计与数据变动

### `get_state`

用途：读取插件总览状态。

请求入口：`POST /plugins/run`，`name=ha_manager_local`，`func=get_state`

返回核心字段：

```jsonc
{
  "role": "standby",
  "desired_role": "standby",
  "switch_status": "idle",
  "external_closed": true,
  "checks": [],
  "steps": [],
  "step_list": {},
  "log": []
}
```

数据变动：读取 `config.json`、`role`、`step_state.json`、`actions.log`，生成 `state.json`，并刷新 `ha_manager_title_state.json`。

### `get_step_script`

用途：获取当前步骤脚本，供代码编辑框展示。

请求参数：

```jsonc
{
  "step_key": "master_openresty",
  "target_role": "master"
}
```

返回示例：

```jsonc
{
  "step_key": "master_openresty",
  "target_role": "master",
  "title": "启动 OpenResty",
  "script": "systemctl unmask openresty || true\nsystemctl enable openresty || true\npython3 /www/server/jh-panel/plugins/openresty/index.py start"
}
```

数据规则：返回步骤脚本本体，不返回运行前置包装。

### `run_step`

用途：执行当前步骤。

请求参数：

```jsonc
{
  "step_key": "promote_mysql",
  "target_role": "master",
  "run_id": "FLOW_xxx_LOCAL_xxx",
  "script_content": ""
}
```

数据变动：

- 写入 `/www/server/ha_manager_local/logs/steps/<run_id>.log`
- 更新 `/www/server/ha_manager_local/data/step_state.json`
- 更新 `/www/server/ha_manager_local/data/config.json`
- 返回 `state_snapshot` 给前端刷新状态

执行规则：

- `script_content` 有内容时，执行前端提交的脚本。
- `script_content` 为空时，执行 `flow_config.json` 中配置的脚本。
- 所有脚本统一在 `/www/server/jh-panel` 目录下执行。
- 后端自动追加执行包装：切换目录、输出当前目录、输出步骤名、`set -e`、`set -x`。

### `read_step_log`

用途：读取步骤日志文件。

请求参数：

```jsonc
{
  "run_id": "FLOW_xxx_LOCAL_xxx",
  "log_path": "/www/server/ha_manager_local/logs/steps/FLOW_xxx_LOCAL_xxx.log"
}
```

数据规则：优先按 `run_id` 读取；没有 `run_id` 时按 `log_path` 读取；`log_path` 只允许读取 `/www/server/ha_manager_local/logs/steps/` 目录下的文件。

### `health_check`

用途：按当前角色执行自检。

请求入口：`POST /plugins/run`，`name=ha_manager_local`，`func=health_check`

返回核心字段：

| 字段 | 说明 |
| --- | --- |
| `checks` | 自检明细列表，每项包含 `group`、`name`、`expected`、`actual`、`status` |
| `health_status` | `normal` / `warning` |
| `health_text` | `正常` 或 `自检异常 N 项` |
| `external_closed` | OpenResty 是否处于关闭状态 |

检查数据：OpenResty 状态、rsyncd 任务、lsyncd 服务、计划任务状态、监控提醒状态、同步公钥授权状态、角色标记。

数据规则：该接口只刷新并返回自检结果；切换流程中的 `master_check`、`standby_check` 步骤会调用该接口，并把异常摘要写入 `warning_msg`。

## 切换流程数据

### 从->主

| 分组 | 关键动作 |
| --- | --- |
| 数据库升为主 | 确认 MySQL 正常；调用 `mysql-apt delete_slave` |
| 文件同步开启 | 开启 lsyncd 定时同步；启用 rsyncd 同步任务；启动 lsyncd |
| 备份策略调整 | 移除同步公钥授权；关闭数据库和 xtrabackup 备份；开启网站/插件配置备份 |
| 计划任务调整 | 关闭网站/插件配置恢复；开启 SSL 证书续签 |
| 通知规则调整 | 开启邮件、主从异常、Rsync 异常、SSL 到期提醒 |
| 打开 OpenResty | 解除 mask；启用自启动；启动 OpenResty |
| 标记为主机 | 写入 `role=master` |
| 主机自检 | 按主机期望检查 OpenResty、同步任务、计划任务、监控提醒和角色标记 |

### 主->从

| 分组 | 关键动作 |
| --- | --- |
| 关闭 OpenResty | 停止、禁用并 mask OpenResty |
| 数据库降从 | 调用 `mysql-apt init_slave_status`；调用 `mysql-apt check_slave_status` 检查主从状态 |
| 文件同步关闭 | 停用 rsyncd 同步任务；停止 lsyncd；清理 rsync 进程；关闭 lsyncd 定时同步 |
| 通知规则调整 | 关闭主从异常、Rsync 异常、SSL 到期提醒 |
| 备份策略调整 | 授权同步公钥；开启数据库和 xtrabackup 备份；关闭网站/插件配置备份 |
| 计划任务调整 | 开启网站/插件配置恢复；关闭 SSL 证书续签 |
| 标记为备机 | 写入 `role=standby` |
| 备机自检 | 按备机期望检查 OpenResty、同步任务、计划任务、监控提醒和角色标记 |

## 前端交互与数据流

### 打开切换弹框

触发：点击“备->主”或“主->备”。

数据流：前端读取 `flow_config.json`，创建新的 `flow_run_id`，生成当前目标角色的步骤列表。每次打开弹框都是新任务。

### 执行当前步骤

触发：点击步骤详情里的“执行当前步骤”。

数据流：前端调用 `get_step_script`，打开代码编辑框；用户点击编辑框“执行”后，前端把脚本作为 `script_content` 提交给 `run_step`。

### 继续执行

触发：点击右下角“继续执行”。

数据流：前端直接调用 `run_step`，不打开代码编辑框；后端执行 `flow_config.json` 中当前步骤的 `code`。

### 日志轮询

触发：步骤开始执行。

数据流：前端每 500ms 调用 `read_step_log`，读取日志文件并刷新日志框。

### 自检刷新

触发入口：总览页“重新自检”、自检状态页“刷新自检”、切换流程中的 `master_check` / `standby_check` 步骤。

数据流：前端调用 `health_check`；后端按当前角色计算期望状态并返回 `checks`；前端刷新总览页异常数量和自检状态页明细。流程自检发现异常时，步骤仍标记为完成，并在步骤详情里显示黄色异常提示。
